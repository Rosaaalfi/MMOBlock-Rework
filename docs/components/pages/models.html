Models & BDEngine

Native 3D model rendering via display-entity packets with keyframe animations, collision fake-blocks, and BDEngine scene support.

MMOBlock features a packet-based 3D model rendering system that loads and displays BDEngine models — a Minecraft model format designed for tools like BlockBench. Models are rendered per-player using display entity packets (Block Display, Item Display, Text Display) with full support for keyframe animations.

BDEngine models do NOT require the external Block Display plugin or persistent Bukkit display entities — they are rendered entirely via packets, making them invisible to other plugins and immune to entity limits.

1. How It Works #

The BDEngine rendering pipeline works as follows:

  1. Loading — Models are loaded from models/bdengine/ on plugin startup. The parser supports raw JSON, GZIP-compressed JSON, and PRJ2 binary project files.
  2. Parsing — The scene JSON is parsed to extract display parts (BlockDisplay, ItemDisplay, TextDisplay) with their transformation matrices, and animation keyframes.
  3. Rendering — When a block with a BDEngine model is near a player, MMOBlock sends per-player display entity packets showing the model. The model is anchored to the block's grid center (X/Z offset by 0.5, Y at block bottom).
  4. Animation — Keyframe animations are sampled into per-tick eased frames using smoothstep interpolation. Each play request is guarded by a sequence ID to prevent stale frames from overriding newer animations.

2. Model Format #

BDEngine models are created in modeling tools like BlockBench and exported as .bdengine files. These files are placed in plugins/MMOBlock/models/bdengine/.

Supported file formats:

Format Extension Description
Raw JSON .bdengine Uncompressed JSON scene file.
GZIP JSON .bdengine GZIP-compressed JSON scene file (detected automatically).
PRJ2 Binary .bdengine Structured binary project format with a scene.json entry.

Display part types:

Type Description
BLOCK Rendered as a Block Display — shows a Minecraft block with a material (e.g., minecraft:stone).
ITEM Rendered as an Item Display — shows a Minecraft item with optional enchantment glow.
TEXT Rendered as a Text Display — shows text with font and styling.

Each part has a transformation matrix (4×4) defining its position, rotation, and scale relative to the model origin. Models also define brightness values for sky light and block light.

3. Model Placement & Positioning #

BDEngine models are anchored differently from their visual bounds:

Axis Anchor Detail
X Block center Offset by 0.5 from the block's west edge.
Z Block center Offset by 0.5 from the block's north edge.
Y Block bottom Anchored to the parsed model's visual bottom, so the model sits on the ground.

This centering means asymmetric models (like trees) keep their authored trunk/origin centered on the block, rather than the visual bounds center.

MMOBlock's BDEngine positioning anchors X/Z to the editor grid block center (0.5, 0.5) rather than the parsed visual bounds center, so asymmetric models such as trees keep their authored trunk/origin centered on the block. Y remains anchored to the parsed model bottom.

4. Animations #

BDEngine models can include keyframe animations. MMOBlock reads these from the model file and plays them per-player via packet updates.

Animation Names & Resolution

Animation names in the BDEngine scene are automatically mapped:

BDEngine Name Maps To Config Key
animation spawn onSpawn.name
animation_2 click / hit / mine onClick.name
custom name Resolved via listAnim table Any name in config

Animation Config

Animations are configured in the block definition under modelType.bdengine:

modelType: bdengine: enabled: true model: iron_ore onSpawn: name: spawn timeline_length: 0.5 mode: once onClick: name: click timeline_length: 0.5 mode: once
Option Type Description
name String Animation name. Resolved through the BDEngine scene's animation table.
timeline_length Double Total playback duration in seconds.
mode String Playback mode: once (play once, restore rest pose) or loop (repeat indefinitely).

Playback Details

  • Keyframes are sampled into per-tick eased frames using smoothstep (Hermite) interpolation.
  • Each play request is assigned a sequence ID — stale scheduled frames from a previous animation are ignored if a newer animation started.
  • After a once animation completes, the model returns to its stored base display parts (not a computed delta transform), so final rest keyframes render upright.
  • Animations matching a group's bind/rest transform render from the stored base display parts exactly, not from a computed delta, preventing residual tilted or scaled transforms.

5. Collision #

Since BDEngine models are packet-only (no real entity in the world), you can optionally place fake collision blocks that act as solid barriers.

bdengine: collision: type: block block: minecraft:barrier position: - "0, 0, 0"
Option Type Description
type String Collision type. Currently only block.
block String Material for the fake collision block (e.g., minecraft:barrier).
position List List of "x, y, z" offsets relative to the model origin.
Collision blocks are fake — they are sent to clients via block change packets and do not actually exist in the world. They provide visual blocking only.

6. Configuration in Block Definition #

Here is the complete BDEngine section within a block definition:

# Complete BDEngine model configuration in a block definition modelType: bdengine: enabled: true model: iron_ore size: 2.0 collision: type: block block: minecraft:barrier position: - "0, 0, 0" onSpawn: name: spawn timeline_length: 0.5 mode: once onClick: name: click timeline_length: 0.5 mode: once
Option Type Default Description
enabled Boolean false Enable BDEngine model rendering for this block.
model String — Model file name (without path/extension). Loaded from models/bdengine/.
size Double 1.0 Scale multiplier for the entire model.
collision Section — Fake collision block configuration.
onSpawn Section — Animation played when the block spawns/respawns.
onClick Section — Animation played on each click.

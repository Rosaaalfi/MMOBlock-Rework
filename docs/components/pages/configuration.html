Configuration Reference

Full documentation for every option in config.yml — the central configuration file for MMOBlock.

The config.yml file is automatically generated inside plugins/MMOBlock/ when the plugin first loads. All settings have sensible defaults, so you can start with minimal changes and gradually customize.

After changing config.yml, run /mmoblock reload to apply changes without restarting your server.

1. General Settings #

Option Type Default Description
debug Boolean false Enables verbose debug logging to the console. Useful for troubleshooting configuration issues or tracking down bugs.
bStats Boolean true Send anonymous usage statistics to bStats. Helps the developer understand plugin adoption and version distribution. Set to false to opt out.
updateChecker Boolean true Check for new versions on voxel.shop on startup. A notification is logged when an update is available.
lang String en-us Language file to use for in-game messages. Corresponds to a file in the lang/ folder (e.g. en-us.yml, id-id.yml, ja-jp.yml).
# Logging & diagnostics debug: false # Enable verbose debug logging bStats: true # Send anonymous stats to bStats updateChecker: true # Check for updates on startup lang: en-us # Language file (lang/en-us.yml)

2. Asset Extraction #

Option Type Default Description
extractDefaultAssets Boolean true Extract example configuration files from the plugin JAR into the plugin data folder on every reload. When true, files in blocks/, drops/, tools/, nodes/, lang/, and models/ are overwritten with the bundled defaults. Set to false after your first setup to prevent overwriting your custom configurations.
extractDefaultAssets: true # Overwrite example files on reload
Set extractDefaultAssets: false after your initial setup to avoid losing your custom block/drop/tool definitions on future reloads or plugin updates.

3. Interaction Settings #

Option Type Default Description
interactionThrottleMs Integer 1000 Minimum time (in milliseconds) between interactions with the same block or entity. Prevents accidental double-clicks or spam from rapidly breaking/placing blocks.
interaction.reach Double 6.0 The maximum reach distance in blocks for interacting with MMOBlock entities. Players beyond this range cannot interact. This is the default reach used in block lookup.
interaction.legacy-reach Double 6.0 Fallback reach distance used in legacy interaction checks. Only relevant if you have custom or older interaction handling.
interaction.look-check-interval-ticks Integer 2 How often (in ticks) the plugin checks what block the player is looking at for interaction purposes. Lower values = more responsive but slightly more CPU usage.
interactionThrottleMs: 1000 # Anti-spam throttle (ms) # Advanced interaction options (configured in code, not in default config.yml) # interaction.reach: 6.0 # interaction.legacy-reach: 6.0 # interaction.look-check-interval-ticks: 2

4. Database Configuration #

MMOBlock supports two database backends: H2 (embedded, file-based, default) and MySQL (remote server). The database stores placed blocks, nodes, and respawn timestamps.

4.1 H2 (Embedded)

Option Type Default Description
databases.h2.enabled Boolean true Enable the H2 embedded database. Disable this when using MySQL.
databases.h2.file String .caches/data Path to the H2 database file, relative to the plugin data folder. The database is stored at plugins/MMOBlock/.caches/data by default. Can be an absolute path.
databases: h2: enabled: true # Use embedded H2 database file: .caches/data # Relative to plugins/MMOBlock/

4.2 MySQL

Option Type Default Description
databases.mysql.enabled Boolean false Enable MySQL database. Set to true and configure the connection details below. The MySQL connector JAR is automatically downloaded on first startup.
databases.mysql.host String localhost MySQL server hostname or IP address.
databases.mysql.port Integer 3306 MySQL server port.
databases.mysql.database String voxelshop Database name to use. The database must exist — the plugin does not create it automatically.
databases.mysql.username String root MySQL user with read/write access to the database.
databases.mysql.password String password MySQL user password.
databases: mysql: enabled: true # Switch to MySQL host: localhost port: 3306 database: mmoblock username: root password: your_secure_password h2: enabled: false # Disable H2 when using MySQL
When switching from H2 to MySQL (or vice versa), the plugin will start with an empty database. Existing data is not migrated automatically. Shut down your server, export your H2 data, and import it into MySQL if needed.

4.3 Database Tables

The plugin automatically creates the following tables on startup:

Table Purpose
mmoblock_block Stores placed custom block data — location, type, facing direction, mining status, and origin coordinates.
mmoblock_respawn Tracks respawn timestamps for each block (used for respawn timers). Foreign key to mmoblock_block.
mmoblock_node Stores placed node entities — node ID, world, and position.

The mmoblock_block table also includes optional origin_x, origin_y, origin_z columns for multi-block structures, automatically migrated on existing databases.

5. Progress Bar #

The progress bar is displayed to players while mining MMOBlock custom blocks. It uses MiniMessage color codes for rich formatting.

Option Type Default Description
progressbar.progressing String &a| Character(s) used for the filled (progressed) portion of the bar. Supports legacy color codes (&a = green).
progressbar.noprogress String <gray>|</gray> Character(s) used for the unfilled portion. Supports MiniMessage format (<gray>).
progressbar.barlength Integer 16 Total length of the progress bar in characters. For example, barlength: 20 creates a 20-segment bar.
progressbar: progressing: "&a|" # Completed segment noprogress: "<gray>|</gray>" # Remaining segment barlength: 16 # Total bar length

6. Hologram Settings #

MMOBlock uses a packet-based hologram system for displaying floating text, items, and block models. All rendering is done client-side via Minecraft packets — no armor stands or entities are used.

6.1 Spacing & Offset

Option Type Default Description
hologram.packet.spacing.text Double 0.25 Vertical spacing between text lines in the hologram.
hologram.packet.spacing.item Double 0.30 Vertical spacing between item display entities.
hologram.packet.spacing.block Double 0.30 Vertical spacing between block display entities.
hologram.packet.offset.text Double 0.00 Additional vertical offset applied to text display entities.
hologram.packet.offset.item Double 0.00 Additional vertical offset applied to item display entities.
hologram.packet.offset.block Double 0.00 Additional vertical offset applied to block display entities.

6.2 Performance

Option Type Default Description
hologram.packet.maxUpdatesPerTick Integer 200 Maximum number of hologram packets that can be sent per tick. Prevents packet floods when many holograms update simultaneously. Minimum: 16.
hologram.packet.animationUpdateIntervalTicks Integer 1 How often (in ticks) hologram animations advance. Default is every tick (20 times/second). Increase to reduce CPU usage for animated holograms.
hologram.packet.proximityScanIntervalTicks Integer 20 How often (in ticks) the plugin scans for nearby players to send hologram packets. Default is every 20 ticks (1 second). Increase for large servers with many holograms.
Hologram spacing values work like a "step" between each line. A spacing.text of 0.25 means each text line is rendered 0.25 blocks above the previous one. Adjust these values to fine-tune your hologram appearance.
hologram: packet: maxUpdatesPerTick: 200 spacing: text: 0.25 item: 0.30 block: 0.30 offset: text: 0.00 item: 0.00 block: 0.00

7. ECS Settings #

MMOBlock uses an Entity-Component-System (ECS) architecture for block state management. These settings control ECS behavior.

Option Type Default Description
ecs.spawn-managed Boolean false When enabled, the ECS system manages entity spawning for block display entities. This can help with entity cleanup but may impact performance on large servers.
# ECS system settings (not in default config.yml, can be added manually) # ecs: # spawn-managed: false

8. Full Configuration Example #

Here is the complete config.yml with all options and detailed comments:

# ======================================== # MMOBlock Configuration # ======================================== # -- General -- debug: false # Verbose console logging bStats: true # Anonymous usage statistics updateChecker: true # Check for updates lang: en-us # Language (lang/*.yml) extractDefaultAssets: false # Don't overwrite custom configs # -- Interaction -- interactionThrottleMs: 1000 # Anti-spam (ms) # -- Database -- databases: mysql: enabled: false # Set to true to enable MySQL host: localhost port: 3306 database: mmoblock username: root password: password h2: enabled: true # Default embedded database file: .caches/data # Database file path # -- Progress Bar -- progressbar: progressing: "&a|" noprogress: "<gray>|</gray>" barlength: 16 # -- Hologram -- hologram: packet: maxUpdatesPerTick: 200 spacing: text: 0.25 item: 0.30 block: 0.30 offset: text: 0.00 item: 0.00 block: 0.00
Options not present in the default config.yml (like ecs.spawn-managed or interaction.reach) can be added manually — the plugin reads them with fallback defaults. This keeps the default config minimal while still allowing advanced tuning.
